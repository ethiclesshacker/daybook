Daybook — privacy

Last updated 24 October 2026

Daybook is a personal record kept by one person, for that person. It is not a service offered to the public: there is no sign-up, no other users, and nobody else's data in it.

What it holds

Money (net-worth snapshots, card transactions and points), meals and nutrition, health readings from Apple Health, and a ledger of everyday events — purchases, travel, meetings — mostly extracted from the owner's own email receipts and alerts.

Where it lives

In a Supabase project owned by the same person, behind row-level security, and in a Cloudflare Pages deployment of this site. The jobs that read email run on the owner's own computer; mailbox passwords stay in the macOS keychain and never leave it.

Google user data

Daybook's assistant can read, search, label, draft and send mail in the owner's own Gmail account, with the owner's explicit consent, using the gmail.modify and gmail.settings.basic scopes. Mail content is used only to answer the owner's questions and to carry out actions the owner asks for in that conversation. It is not sold, not shared with anyone, not used for advertising, and not used to train models. Google OAuth tokens are stored only on the owner's computer.

Daybook's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Third parties

Supabase (database and sign-in), Cloudflare (hosting), the owner's bank-aggregation app and the model providers the assistant calls, each for the single purpose of making the app work. None of them is given Google user data.

Deletion

The owner can delete anything at any time from the app, the database or the Google account's third-party access page, and revoke Daybook's Gmail access at myaccount.google.com/permissions.
